# 체크인과 A 기능 연결 수정안

상태: 2026-10-10 사용자 승인. 아래 여섯 서비스의 연결 호출 추가와 실행 순서가 승인되었다. 연결 코드는 구현 대기 상태다.

## 목적과 승인 범위

체크인 회차 시작 당시의 대상 작업과 팀원을 보존하려면, A 기능이 현재 데이터를 바꾸기 전에 도래한 회차를 생성해야 한다. 변경 후에는 확정 정책에 따라 현재 회차의 제외 여부만 반영한다.

수정 대상은 아래 서비스의 체크인 연결 호출, 생성자 의존성 추가 및 관련 검증이다. 기존 API 요청·응답과 CRUD 권한 검사는 유지한다. 이미 승인된 진행률 자동 계산과 이슈 해결 기능은 별도 작업으로 진행한다.

## 파일별 수정 위치

| 서비스 | 변경 전 처리 | 변경 후 처리 | 이유 |
|---|---|---|---|
| ProjectService 생성 | 해당 없음 | 프로젝트·요일 저장 후 최초 일정 등록 | 첫 회차 기준을 보존 |
| ProjectService 설정 변경 | 기존 일정으로 도래한 회차 생성 | 체크인 요일이 바뀌면 새 일정의 적용 시점 기록 | 과거 회차 시각이 새 설정으로 바뀌는 것을 방지 |
| ProjectService 종료 | 도래한 회차 생성 | 진행 중인 미제출 의무 제외, 제출 기록과 이미 확정된 누락 보존 | 종료 후 쓰기 차단과 통계 일관성 |
| TaskAssignmentService 담당자 교체 | 기존 배정으로 도래한 회차 생성 | 명시적으로 해제된 담당자의 해당 작업을 현재 대상에서 제외 | 중간 신규 배정은 다음 회차부터 적용 |
| TeamService 가입 승인 | 승인 이전 상태로 도래한 회차 생성 | 신규 참여는 다음 회차부터 적용 | 회차 중 가입자가 현재 분모에 추가되는 것을 방지 |
| TeamService 내보내기 | 도래한 회차 생성 후 퇴장 사실을 체크인에 먼저 기록 | 기존 담당 정리와 내보내기 실행 | 퇴장자는 현재 의무를 유지하면서 제출만 차단 |
| TaskService 작업 취소 | 취소 이전 상태로 도래한 회차 생성 | 현재 대상에서 취소 작업 제외 | 취소 전 기록 보존 |
| TaskRelationService 하위 작업 생성·완료 변경·삭제 | 진행률·완료 상태 변경 전에 도래한 회차 생성 | 기존 진행률 자동 계산 실행 | 회차 시작 당시 미완료 작업을 놓치지 않도록 보존 |

TaskRelationService는 앞서 확인 요청한 네 서비스에 추가되는 대상이다. 하위 작업 변경으로 상위 작업이 DONE이 될 수 있으므로 같은 사전 처리가 필요하다.

## 실행 순서와 트랜잭션

1. 기존 프로젝트 잠금과 사용자 권한·입력 검증을 수행한다.
2. 변경 직전 상태로 시작 시각이 지난 회차와 당시 대상을 생성한다.
3. 기존 A 기능의 변경을 실행한다.
4. 담당 해제·취소·종료 등 필요한 체크인 대상 상태를 반영한다.
5. 같은 트랜잭션에서 함께 커밋한다. 체크인 반영이 실패하면 A 변경도 롤백한다.

체크인 서비스는 A 서비스로 다시 호출하지 않도록 구성해 순환 의존성을 피한다. 회차 생성과 제출도 동일한 프로젝트 잠금 규칙을 사용한다. 중복 실행은 DB 고유 제약과 기존 회차 조회로 처리한다.

### 내보내기와 담당 해제 구분

내보내기로 발생한 배정 정리는 일반 담당 해제와 구분한다. 퇴장 사실을 먼저 기록하고, 배정 정리가 현재 체크인 의무를 지우지 않게 한다. 재가입 시 같은 member ID를 사용하더라도 과거 회차의 퇴장 상태와 가입 시점을 보존해 이전 회차 제출 권한을 복원하지 않는다.

### 완료·일정 변경 처리

회차 도중 완료된 작업은 그 회차 대상에 남긴다. 이후 회차에서는 제외한다. 새 일정은 기존 회차의 지각 종료 시각 이후부터 적용하며, 이미 생성된 회차의 시작·마감·지각 종료 시각을 수정하지 않는다.

## DB 변경안

- 기존 V1/V2 마이그레이션은 수정하지 않는다.
- 현재 브랜치의 V3는 작업 이슈 테이블 추가안이다. 원격에 같은 번호가 추가되면 병합 전 번호를 다시 확인한다.
- 체크인 일정 이력·회차·참여자·대상 작업·제출 스냅샷은 후속 PostgreSQL 마이그레이션으로 추가한다. 정확한 번호와 컬럼은 구현 시 원격 상태를 대조해 정한다.
- 기존 체크인 테이블의 과거 대상은 현재 작업 상태로 추측해 채우지 않는다. 기존 데이터가 있으면 보존·전환 방안을 별도로 제시한다.
- 실제 배포 DB에는 이 문서 검토만으로 적용하지 않는다. 브랜치 구현 후 PR과 수동 머지 절차를 따른다.
- ERD는 최종 구현 스키마에 맞춰 함께 갱신한다.

## 검증할 항목

- 회차 생성 재실행과 동시 제출에서 중복 회차·기록이 생기지 않는다.
- 시작·정시 마감·지각 종료 경계, 정시 수정과 지각 최초 제출 규칙이 맞는다.
- 중간 배정·가입은 다음 회차부터, 명시적 해제·취소는 현재 대상 제외로 반영한다.
- 내보내기 후 현재 의무는 남고 제출은 차단된다. 재가입해도 과거 권한은 복원되지 않는다.
- 중간 완료와 일정 변경 이후에도 기존 대상·회차 시각·제출 스냅샷은 유지된다.
- 종료 시 진행 중 미제출 의무만 제외하고 과거 확정 기록은 보존한다.
- A의 기존 권한·인증·CRUD 동작과 승인된 진행률 계산이 유지된다.

## 검토 요청

위 여섯 서비스의 연결 호출 추가와 실행 순서를 승인받은 뒤 체크인 저장·자동 회차·기록 조회 구현을 연결한다. A 기능 자체의 추가 변경이 필요해지면 해당 변경을 따로 제시한다.
