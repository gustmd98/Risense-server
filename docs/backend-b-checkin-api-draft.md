# 체크인 조회·제출 API 초안

작성: 2026-10-09 · 상태: 프론트 협의용 초안, 실행 가능한 API 아님.

## 이번 브랜치의 범위

확정된 회차 시간·전체 대상 제출 규칙을 DB와 분리해 검증한다.
ERD·Flyway 번호가 미확정이므로 마이그레이션, 엔티티 변경, Controller는 추가하지 않는다.
진행률·실제 완료자·이슈 해결 및 산출물 저장 시점은 팀 합의 전까지 구현하지 않는다.
기존 체크인 정책의 산출물 제출 시 저장과 최근 제안한 즉시 저장은 아직 합의되지 않은 대안이다.
이 문서는 확정된 API 계약이나 Swagger 배포 명세가 아니다.

## 제안하는 조회 → 제출 → 재조회 흐름

모든 경로는 Bearer JWT 인증을 요구한다. JWT subject는 사용자 ID이며 프로젝트 멤버 ID와 구분한다.
프로젝트·승인 상태는 A의 ProjectAccess로 확인한다. 클라이언트가 보낸 역할·멤버 ID는 신뢰하지 않는다.

| 메서드 | 제안 경로 | 용도 |
| --- | --- | --- |
| GET | /api/projects/{projectId}/checkins/current | 현재 회차와 내 유효 대상, 내 제출 상태 조회 |
| POST | /api/projects/{projectId}/checkins/{roundId}/submission | 최초 제출 |
| PUT | /api/projects/{projectId}/checkins/{roundId}/submission | 정시 제출 수정 |
| GET | /api/projects/{projectId}/checkins/{roundId}/submission | 내 제출 당시 기록 재조회 |

현재 회차 조회는 회차 식별자, 시작·정시 마감·지각 종료 시각, 서버 시각,
현재 구간(NOT_OPEN/ON_TIME/LATE/CLOSED), 제출·수정 가능 여부와 유효 대상 작업 목록을 제공하는 방향이다.
시간은 ISO 8601의 UTC 또는 명시적인 오프셋을 사용하며 클라이언트 시각으로 판정하지 않는다.
회차가 아직 없거나 대상이 없는 경우는 최초 제출 가능한 빈 회차로 취급하지 않는다.
현재 작업 정보와 이미 제출한 스냅샷은 별도 필드로 제공한다.
최종 응답 필드, 대상 없음·회차 없음 응답, 개인 입력 필드는 ERD 검토 후 확정한다.

제출 요청은 전체 유효 대상의 taskId를 중복 없이 포함한다.
상태·진행률을 클라이언트 수동 입력값으로 저장하지 않고 서버의 최신 정보에서 스냅샷을 만든다.
이슈·링크 요청 필드는 정책 확정 후 추가한다. 값이 바뀌지 않아도 전체 대상을 포함하면 유효하다.

```json
{
  "taskIds": [101, 102]
}
```

위 예시는 전체 대상 검증 부분만 설명한다. 재요청 키와 충돌 감지용 버전 계약을 포함한 최종 요청은 미확정이다.
화면이 열린 사이 대상이 바뀌면 최신 대상을 재조회하도록 안내하고 일부 제출은 저장하지 않는다.
정시 마감 전 수정은 동일한 논리 제출을 갱신하며 최초 제출 시각을 보존한다.
지각 기간은 최초 제출만 허용하고, 지각 종료 정각부터 최초 제출도 허용하지 않는다.
POST 재요청을 PUT 수정으로 취급하지 않는다. 재요청 식별·중복 방지는 DB 설계와 함께 확정한다.

## 검증 순서와 제안 오류

제출 서비스는 하나의 트랜잭션에서 기존 프로젝트 잠금을 사용하고 권한·쓰기 가능 상태·회차 소속을 먼저 확인한다.
그 다음 서버 시간, 기존 제출 유무, 보존된 회차 대상에서 현재 유효한 작업, 충돌 버전을 재검증한다.
현재 담당자 목록만으로 회차 시작 당시 대상을 재구성하지 않는다.
재가입 시 동일 멤버 ID를 재사용해도 내보내기 당시 회차의 제출 권한을 복원하지 않는다.

오류 응답은 기존 ApiError(code, message, fieldErrors) 형식을 사용한다.
다음 코드는 정책 판정 결과의 HTTP 매핑 제안이며 아직 등록된 API가 아니다.

| HTTP | 제안 코드 | 조건 |
| --- | --- | --- |
| 400 | CHECKIN_INVALID_TASK_IDS | taskIds 누락, 중복, null, 0 이하 ID |
| 401 | UNAUTHORIZED | JWT 없음·무효 |
| 403 | PROJECT_ACCESS_DENIED | 승인된 현재 멤버가 아님 |
| 404 | CHECKIN_ROUND_NOT_FOUND | 회차 없음 또는 다른 프로젝트 회차 |
| 409 | PROJECT_NOT_WRITABLE | 종료된 프로젝트 |
| 409 | CHECKIN_NOT_OPEN / CHECKIN_CLOSED | 제출 시간 밖 |
| 409 | CHECKIN_LATE_EDIT_NOT_ALLOWED | 지각 기간 기존 제출 수정 |
| 409 | CHECKIN_NO_TARGETS | 유효 대상 없음 |
| 409 | CHECKIN_TARGETS_CHANGED | 대상 누락 또는 대상 외 작업 포함 |

DB 저장, 요청 멱등성, 이슈·링크 충돌은 이번 순수 정책 클래스의 책임이 아니다.
단순히 이 클래스의 ALLOWED 결과만으로 인증·DB 저장을 허용하지 않는다.

## 저장 구조 검토 사항 — ERD 확정 후 반영

- 회차 시작·정시 마감·지각 종료 시각을 보존하고 프로젝트·회차 날짜의 중복 생성을 막는다.
- 회차별 멤버·작업 대상과 이후 제외 사유를 보존한다. 탈퇴와 일반 담당 해제의 차이를 구분한다.
- 회차·멤버별 논리 제출은 하나이며 최초 제출 시각과 마지막 수정 시각을 구분한다.
- 제출 당시 작업·하위 작업·수행자·산출물 정보를 보존해 이후 변경이 과거 기록을 바꾸지 않게 한다.
- 기존 제한된 진행률 값과 BLOCKED 기반 필드는 자동 진행률·이슈 정책과 대조한다.
- 적용된 V1/V2는 수정하지 않고 번호 조율 후 새 PostgreSQL 마이그레이션을 추가한다.

## 현재 검증 대상

CheckinSubmissionPolicy는 전체 대상의 정확한 일치 여부와 제출 시간·기존 제출 유무만 검사한다.
테스트는 누락·대상 외 ID·중복·잘못된 ID·대상 없음·변경 없는 제출·정시 수정·지각 최초 제출·시간 경계를 확인한다.
실제 HTTP, DB 저장, 동시 요청과 프론트 연동은 서비스 구현 이후 검증한다.
