# B 기능별 PR 제목·본문

먼저 main의 README 문서 커밋을 푸시한다. 이후 순서대로 각 기능 브랜치를 푸시하고 main 대상 PR을 만든다. 앞 PR을 일반 Merge commit으로 머지하면 다음 PR에서 이미 머지한 커밋이 자동으로 빠진다. squash/rebase를 사용한 경우 다음 브랜치의 기준을 먼저 갱신한다.

## 1. feat/task-progress

제목: `feat: 하위 작업 기반 진행률과 완료 상태 자동 반영`

본문:

- 하위 작업 생성·완료 변경·삭제 시 상위 작업 진행률을 자동 계산합니다.
- 항목이 하나 이상이고 모두 완료되면 DONE, 다시 미완료가 생기면 IN_PROGRESS로 전환합니다.
- 취소 작업은 자동 재개하지 않으며 기존 권한은 유지합니다.
- 진행률 계산과 A 작업 관계 서비스 회귀 검증을 완료했습니다.

## 2. feat/task-issues

제목: `feat: 작업 이슈 조회와 즉시 해결 API 추가`

본문:

- 현재 작업 이슈 조회와 체크인 밖 즉시 해결 API를 추가합니다.
- 담당자·관리자 권한과 revision 충돌을 검사합니다.
- V3로 task_issues 테이블을 추가하며 V1/V2는 수정하지 않습니다.
- 신규 이슈의 공유 기본키 저장을 실제 PostgreSQL에서 검증했습니다.

## 3. feat/checkin-lifecycle

제목: `feat: 체크인 자동 회차와 당시 대상 보존`

본문:

- KST 일정 이력·회차·참여자·대상을 V4로 추가합니다.
- A 서비스에 승인된 연결 호출을 추가해 변경 전에 도래한 회차를 보존합니다.
- 담당 해제·취소·내보내기·재가입·종료의 대상 규칙을 반영합니다.
- 자동 스캔과 프로젝트 잠금으로 중복 회차를 방지합니다.
- 기존 legacy 테이블은 유지하고 새 회차는 V4 적용 이후부터 생성합니다.

## 4. feat/checkin-api

제목: `feat: 체크인 전체 제출과 정시 수정·스냅샷 조회`

본문:

- 현재 회차 조회, 최초 제출, 정시 수정, 제출 재조회를 추가합니다.
- 전체 대상 일치와 지각 최초 제출 규칙을 검사합니다.
- requestKey 멱등성과 revision·작업 버전 충돌을 처리합니다.
- 이슈 보고와 제출은 원자적으로 저장하며 제출 당시 작업 정보를 보존합니다.
- API 계약과 Swagger 오류 명세를 제공합니다.

## 5. feat/checkin-history

제목: `feat: 체크인 기록·현황·누적 집계와 통합 검증`

본문:

- 내 기록 커서 페이지, 회차별 팀 현황, 프로젝트 누적 체크인율을 추가합니다.
- 제출 기한이 남은 PENDING과 확정 MISSED를 구분합니다.
- 유효 대상 없는 기록은 집계에서 제외하며 분모 0은 null입니다.
- 실제 PostgreSQL·A 서비스·동시 요청을 포함한 통합 검증을 추가합니다.
- 최종 전체 171개 테스트, IntelliJ 빌드, 실제 JWT HTTP 흐름을 확인했습니다.

리스크 가중치와 실제 수행자 기반 기여도는 이번 PR 범위에 포함하지 않습니다. 공개 Swagger 반영에는 main 머지 이후 Oracle 이미지 갱신이 필요합니다.
